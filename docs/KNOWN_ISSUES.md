# 已知问题

## FD 数据 3 Mbps 尚未通过内部测试

can0 内部回环在若干帧后超时，尝试采样点 / SJW：
`(0.75,1)`、`(0.8,2)`、`(0.75,2)`、`(0.7,2)`、`(0.8,4)` 均未通过。
未确定是内部回环局限、驱动还是时序问题。不能推断外部 3M 必然失败或正常。
4M 未测试，5M 以上未尝试。本版不将 3M 列为合格档位。

## 旧驱动热解绑警告

早期试验从内置旧驱动热解绑时出现重复释放 IRQ 的 WARN。
最终方案重启后直接绑定新驱动，没有再次出现该 WARN。
外部模块引入 taint=4096（O 标志），不等于获得内核上游或原厂支持认证。

## 映射与时钟是板级约束

驱动 probe 将 CAN 时钟设为 300MHz；本机由现有 CPLL1500MHz 分频得到。
不能据此保证任意 BSP 的时钟父级不会受到影响。
虽保留上游其他 compatible 项，本项目只验证 RK3588 两路目标。

## 内部验证工具会重置业务参数

工具固定两路映射，测试后恢复 FD 仲裁1M / 数据5M，不保存调用前业务模式。
使用 assert 作判定，应通过普通 Python 运行，不能用 `python -O`。
其测试运行耗时不是物理线速或有效吞吐测量。

## 外部与长期验证未完成

没有把外部 CAN 收发器、连接器、线束、业务对端、多节点负载、休眠恢复、环境温度和 EMC 作为已通过项。
测试数量和启动绑定通过不构成生产放行结论。
